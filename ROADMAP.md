## Near-term candidates

Make the recovered directory behave like active infrastructure through sparse
background process motion and meaningful reactions to hover, focus, dwell,
selection, tab return, and pointer departure. Detailed scope and validation live in
`docs/EXPANSION_SESSIONS.md`.

### State migration

Implemented and merged through Milestone 7. A valid schema-version-1
cookie is normalized and coarsened into a bounded schema-version-2

expired, unavailable-storage, and multi-tab erasure paths are explicit and

### Further revisit density

Continue deepening existing pages after the implemented archive, Camera 06, and
operator branches. Browser-only progression
should support drastic, authored revisit states: pages may recompose their
layout, replace document modes, alter available controls, contradict earlier
records, or change visual scale. These changes should feel wild because the
archive has entered a different operational state, not because effects were
chosen randomly.

Candidate mutations:

- root terminal recognizes specific completed interactions;
- inode changes according to invitation and return history;
- archive hierarchy and composition shift according to first-visited room;
- Camera 06 changes reconstruction mode after later-route residue;
- choir changes between carrier, transcript, and retained-silence modes;
- staff register and dead letter compete to define the active record;
- 404 responses vary based on the shape of the requested path.

Each mutation should reveal one new implication, not merely display a higher
counter or revise a single line. Preserve at least one route-specific anchor so
the visitor can recognize the severity of the change. New durable conditions
must use explicit, versioned, first-party local state with migration behavior.

The one-time aperture slip is the current model for high-impact manifestations:
rare, state-earned, non-repeatable, and unexplained. Do not make eyes a recurring
brand device.

### Invitation refinement

The current witness token is the prior visitor's random trace ID and is not
verified server-side. Possible directions:

- invitation-specific opening copy;
- pages that distinguish invited and uninvited traversal;
- a burden-transfer interpretation;
- a later callback to the inviter's token without identifying either person.

Avoid building accounts, identity lookup, or invasive cross-visitor tracking.

### Apparent transfer log — deployed with reconciliation placement

After an explicit terminal operation, rapidly stream recovered paths,
checksums, ownership changes, response sectors, and trace-derived records until
the visitor can no longer comfortably follow the volume of activity. The event
should resemble a transfer or installation at first glance while remaining
technically honest: no browser download, local file, filesystem permission, or

Grandfathered completed traces replay a condensed receipt; reduced motion is
discrete, transient output does not flood live regions, and no file, download,
permission, host claim, or external request is introduced. ADR 0013 supersedes
ADR 0009's late placement.

## Medium-term possibilities

### The outside / digital horizon — implemented and deployed

Create one major scale composition that breaks the visitor out of close
document interfaces:

- foreground: a dark structural silhouette, potentially a city, tower, gantry,
  or machine complex;
- scale cues: rails, apertures, door-like voids, maintenance lights, or another
  human-sized detail without a confirmed human figure;
- background: an enormous receding field of green process text and address
  residue;
- motion: extremely slow parallax or drift, with a still reduced-motion version;
- interpretation: interior of ORISON, network topology, remembered city,
  simulation, infrastructure, or visual metaphor;
- copy: little or none.

The selected implementation is the state-earned `/extent/` interstitial after
Operator. It is not a recurring background or recovered object. Operator forces
the detour once; later history/direct replay is still and the ordinary archive
return is restored.

### Additional recovered objects

Possible object families:

- a process table containing a task that began after the page loaded but has an
  earlier start time;
- a map with no geographic coordinates, only browser navigation relationships;
- a maintenance transcript where redactions shrink on revisit;
- a queue of observers where the current trace is not last;
- a failed backup that contains only records of actions not yet taken.

New objects must earn their route by adding a distinct interaction or inference.

### Session-scale time

Use first-visit time and elapsed real time to change documents across days.
Examples include delayed delivery, expired forecasts, and an object that becomes
available only after absence. Keep all timing local unless a later ADR accepts a
backend.

### Sound language — implemented

The generated audio grammar now uses low carriers, phase relationships, relay
fragments, retained silence, and revisit changes. It remains user-initiated,
voice-free, local, and independent of microphone access or recorded assets.

### False exterior

Add plausible non-experience surfaces—status text, abandoned documentation, or
a sparse index—that deepen discovery without turning the project into a normal
marketing website. The terminal should remain the canonical apex experience.

## Long-term questions

- Should ORISON ever have server-side state, or is local isolation essential to
  its meaning?
- Should two invited visitors ever affect one another indirectly?
- Is there a finite ending, a cyclical ending, or only deeper administrative
  layers?
- Can the site use time, cache, HTTP status, or subdomains as narrative media
  without compromising reliability?
- Should a later phase include a downloadable artifact, and can it remain safe
  and clearly fictional?
- Can ORISON create a sense of a larger network while making no third-party
  requests?

These require explicit architectural and privacy decisions before work begins.

## Rejected or constrained directions

- Gore, jumpscares, scream audio, and shock imagery.
- Camera, microphone input, geolocation, clipboard, local-file, credential, or
  contact access.
- Secretly collecting exact identity or sending a fingerprint to a backend.
- Exposing the home IP or opening router ports.
- A complete lore document that resolves ORISON.
- A conventional account system, dashboard, or content-management layer.
- Copying FAUUX or any other inspiration's HTML, layout, writing, or assets.
- Visual complexity that exists only to say “glitch.”
