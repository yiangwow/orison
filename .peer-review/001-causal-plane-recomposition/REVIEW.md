## Findings

### [MINOR-1] Unpack animation lacks the interruption token that reconciliation has, so a bfcache restore can replay it over a re-booted screen
- File: index.html:760-767 (loop), index.html:903-909 (pagehide handler)
- Problem: `runReconciliation` is cancelled via `reconciliationToken`, which the `pagehide` handler bumps, but the `unpack()` sequence loop has no equivalent guard and `pagehide` does not reset `extracting` or bump a token. `ORISON.page` re-renders on every `pageshow` (assets/orison.js:579-582), including back/forward-cache restores.
- Evidence: Start `unpack orison.zip`, navigate away mid-animation via the URL bar, then press Back. `enter()` → `boot()` calls `output.replaceChildren()` and renders the pre-unpack fiction ("1 compressed object found"), after which the frozen unpack timers resume, interleave the remaining sequence lines into the re-booted output, and write `unpacked` (index.html:767) while the surrounding screen claims the archive is still compressed. The interruption test at tests/verify.py:325-331 covers full reload (flag correctly not written) but not the bfcache path.
- Suggestion: Mirror the reconciliation pattern — check `bootToken` (or a dedicated token bumped on `pagehide`) inside the unpack loop and return before the flag write.

### [MINOR-2] `response-attached` can now be earned by a trace that never unpacked, leaving the root's boot narrative out of sync
- File: index.html:402-412, index.html:658-694
- Problem: `attachmentEarnable` requires only `operator-occupied` plus five answers, not `unpacked`. A visitor using direct hidden-path URLs (examination → operator → extent → operator) can satisfy it without ever unpacking; the root then offers and accepts `reconcile response 00000000` and writes `response-attached`, but every boot status line reporting recovery/reconciliation state is inside the `unpacked` branch (index.html:668-688), so the terminal keeps showing the pre-unpack fiction with no reconciled acknowledgment. The pre-change code could not reach this state because attachment ran only inside `unpack`.
- Evidence: Seed `orison_trace_v2` with `flags: ['operator-probe','operator-occupied']` and five answers but without `unpacked` (the same shape tests/verify.py:271-296 uses, minus `unpacked`): `commandHint` (index.html:414-421) returns "run: reconcile response 00000000" while `boot()` prints '1 compressed object found' and 'Type "unpack"…'.
- Suggestion: Either include `unpacked` in `attachmentEarnable`, or acknowledge the reconciled state in the non-unpacked boot branch.

### [NIT-1] `reducedMotion` is sampled once at load while `pause()` re-queries the media query live
- File: index.html:357 vs index.html:698-703
- Problem: Toggling the OS reduced-motion setting mid-session yields mixed behavior — the reconciliation branch choice uses the stale value while pause durations use the live one.
