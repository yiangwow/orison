# ADR 0013: Recompose the causal system and recovered-record planes

Date: 2026-07-22

Status: Accepted; ending, Parent hierarchy, scale, and manifestation timing
amended by ADR 0015

## Context

The Consequential Handoff Pass made state changes legible, but the complete
journey still read as a set of individually designed pages. The opening
terminal carried the strongest visual and mechanical language, while its first
unpack was less consequential than the later repetition of the same command.
The late sequence also routed an Operator action labelled as a directory return
through Extent, then sent Extent to Archive before the visitor could compare the
same Operator endpoint in its transformed state.

Archive mixed Parent Process and detached-child controls into the recovered-
record index. Its first-access derivation could reorder and enlarge a record,
so current operations, historical interpretation, and recovered evidence did
not have stable visual jobs.

The correction must preserve the hidden paths, local-only version-2 trace,
earned `response-attached` and `operator-occupied` meanings, interrupted-
operation behavior, existing valid traces, native Back, reduced motion,
privacy, erasure, and route-specific compositions. It must not disclose later
journey evidence during initial recovery or turn every surface into a terminal.

## Decision

Treat the terminal and shared receiver as ORISON's causal system plane. Treat
serif and bounded bone-paper surfaces as recovered records and human
interpretation. Both planes use one palette hierarchy: near-black foundation,
luminous green for ORISON and actionable state, ambient green for nonessential
system residue, bone for recovered content, grey for metadata, and red only for
faults, absence, and unresolved work.

Make the first `unpack orison.zip` the sole unpack operation. It performs a
four-phase archive inspection, damaged-directory parse, detached-inode
recovery, and read-only mount. Its output is derived only from the archive and
writes `unpacked` after the complete sequence. Interruption therefore leaves
the operation unearned. Revisit renders a condensed recovery receipt.

Supersede ADR 0009's placement of response attachment inside a repeated
unpack. After `operator-occupied` and five retained answers, the root exposes
the distinct command `reconcile response 00000000`. Reconciliation derives a
ledger from the current local trace and writes `response-attached` only after
its final line. Repeated unpack never attaches a response. Existing valid
version-2 traces with `response-attached` render the completed reconciliation
receipt without conversion.

Close the Operator interruption as one comparison loop: unresolved Operator
offers `attempt archive return`, which opens Extent; Extent's sole egress
returns directly to the same Operator route; that revisit occupies the
Operator and makes the root reconciliation return primary. Archive is not
inserted between Extent and transformed Operator. This amends the placement
described by ADRs 0005, 0006, and 0012 without changing the Extent or Operator
routes or flags.

Give Archive's columns stable jobs. The left column contains current
interpretation and current operations, including the response record, Parent
Process control or receipt, and detached-child continuation. The right column
contains only stable recovered records in this order: Camera 06, Weather 19,
Integrity 32, Carrier 44, Staff 71, Letter 00, Operator --. State may reveal a
record or mark the first source in place, but it must not reorder the index or
promote current operations into the recovered-record hierarchy.

## Consequences

- The causal rhythm becomes unpack, evidence journey, unresolved Operator,
  Extent interruption, transformed Operator, explicit reconciliation, ordered
  Archive, Parent Process, and detached-child requests.
- `response-attached` keeps its schema and Parent eligibility meaning, but its
  new causal trigger is explicit reconciliation rather than repeated unpack.
- Existing v2 records, migration rules, expiry, invitation handling, and full
  erasure remain unchanged; no route, flag, schema, asset, backend, or
  infrastructure dependency is added.
- Keyboard activation, native Back, reload, revisit, and reduced motion must
  preserve the same earned boundaries. The animated and reduced-motion paths
  write flags at the same final operation boundary.
- Desktop visual validation must distinguish useful document variation from
  unearned palette and hierarchy changes. Mobile implementation remains a
  separate scope.
- Behavioral rollback may restore the prior route links, Archive placement,
  and root presentation while keeping all allowlisted flags as inert retained
  values. No state conversion or infrastructure rollback is required.
