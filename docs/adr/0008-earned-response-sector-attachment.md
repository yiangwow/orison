# ADR 0008: Earn the response-sector attachment at the root terminal

Date: 2026-07-17

Status: Superseded by ADR 0009; late trigger replaced by ADR 0013

## Context

Milestone 8 requires an explicit apparent transfer operation whose visible
volume exceeds the visitor's expected source material while remaining
technically honest. The event must use real retained ORISON state, preserve the
restrained opening terminal and command-driven mount, avoid downloads and host
modification claims, give reduced motion a discrete result, and end with a
meaningful progression change.

The repeat examination terminal is too close to the qualification sequence and
would overload its accepted mount contract. Adding an operational input to the
recovered directory would pre-empt the separate future requirement for one
consequential archive intervention. The root recovery terminal already owns
explicit command input and is canonically altered by late progression.

Milestone 7 provides a bounded browser-only version-2 record containing enough
coarse route, answer, command, modality, refusal, hold, and progression evidence
to author the log without retaining new high-resolution observations.

## Decision

Place the operation in the root terminal and expose the exact command
`recover --attach 00000000` only after `operator-probe` and all five retained
answers exist.

Open with plausible archive recovery, inode, checksum, ownership, permission,
and response-sector lines. Then accelerate through a locally reconstructed
ledger containing several values from the accepted version-2 trace. Do not
persist the visual transcript, timing, or raw command.

At the final operation, add the allowlisted `response-attached` flag and render
the response sector as assigned to the current trace. The root reports the
attached response source on later boot, and the archive adds a response-source
record without replacing the first-opened hierarchy. This late earned state
originally ended with an explicit sentence explaining the examination
inversion.

Replay uses the same command and presents a condensed completed ledger. It does
not replay acceleration or the moment of reassignment and does not write the
flag again. Reduced motion renders the complete ledger at once. Transient visual
lines are hidden from accessibility APIs; a separate polite status announces
only the start/review and final assignment.

The full trigger/state/replay, visible-state, accessibility, privacy, and
rollback contracts are part of this decision and live in
`docs/APPARENT_TRANSFER_LOG.md`.

Version-1 migration must discard `response-attached` even if a malformed or
crafted legacy cookie contains it, because no legitimate v1 trace could have
completed this operation.

## Consequences

- The initial terminal, extraction, original commands, examination, and mount
  remain quiet and unchanged.
- The late root return gains one explicit, keyboard-accessible consequential
  operation rather than ambient terminal noise.
- Multiple visible lines vary deterministically with real retained ORISON state
  while raw input and exact timing remain unstored.
- The accepted flags vocabulary grows by one without changing version, record
  shape, request exposure, size ceiling, retention, or erasure behavior.
- Navigating away before the final operation leaves no completion state.
- Replay remains useful evidence but loses the original escalation and state
  transition.
- A behavioral rollback should keep the flag allowlisted; a full Milestone 7
  revert may discard it as an unknown value with no conversion requirement.
- Tests must cover earned and unearned triggers, typed and quick activation,
  real state-derived lines, reduced motion, keyboard focus, screen-reader
  status, interrupted navigation, replay, malformed state, storage bounds,
  trace erasure, the complete existing journey, and zero external requests.
