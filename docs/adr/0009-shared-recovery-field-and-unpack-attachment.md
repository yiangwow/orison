# ADR 0009: Share recovery pressure and attach the response during unpack

Date: 2026-07-17

Status: Accepted; response-placement decision superseded by ADR 0013

## Context

After Milestones 7 and 8 were deployed, browser-history restoration exposed two

## Decision

pressure as a shared background on every rendered HTML surface. Preserve each
route's existing foreground composition, palette, interaction, and stateful
hierarchy. Restart the recovery and receiver animations explicitly on every
`pageshow`; keep the same stateful depth as a still reduced-motion composition.

Make the detached inode instrument larger at wide apertures without adding a
new panel, route, control, or decorative animation.

Keep response attachment earned by `operator-probe` and five retained answers,
but run it as an internal phase of `unpack orison.zip`. A standalone typed

`response-attached` flag, render the same bounded state evidence, and append the
recovered URL as the final output. Remove the explanatory examination sentence

On history restoration, reconstruct the examination mount control as enabled.

## Consequences

- Every route visibly belongs to one running recovery system while retaining a
  route-specific foreground and legible content hierarchy.
- History restoration no longer depends on browser-specific CSS animation or

- The original unpack command now owns discovery, attachment, and final URL

  earned.
- The accepted version-2 schema, size ceiling, migration, request exposure,
  privacy boundary, `response-attached` meaning, and erasure behavior do not

- Reduced motion remains complete and still. No new sound, permission, file,
  download, dependency, backend, or external request is introduced.
- Behavioral rollback may restore the root-only field and standalone trigger
  while keeping `response-attached` allowlisted until expiry or erasure. No
  state conversion is required, and Cloudflare/nginx configuration is unchanged.
